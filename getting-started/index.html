    Getting started

    Goal: get both tools pointed at one project folder and confirm the agent layer is wired. ~15 minutes.

    What you need

    • A Claude account with Claude Code and Cowork access.
    • git, and clone/read access to the project repo (for TAP work, claude-cowork-code).
    • Node.js (for the Claude Code CLI install method below).
    • For TAP LMS specifically: a working Frappe bench on your machine — see SETUP.md. Not needed if you're only planning, or starting a non-Frappe project.

    1. Get the project folder

    git clone <your-project-repo>
cd <your-project>

    Everything — code, docs, the .claude/ agent layer — lives under this one folder. Both tools open it.

    2. Install Claude Code (the build half)

    Claude Code is the CLI with a terminal. The common install:

    npm install -g @anthropic-ai/claude-code
claude            # run inside the project folder; sign in when prompted

    (See the official Claude Code docs for the latest install options, including the native installer and IDE extensions.) On first run in the folder, Claude Code auto-loads CLAUDE.md as context.

    3. Open the same folder in Cowork (the plan half)

    Cowork is the planning half. Open the same project folder there. Cowork can read and edit files (specs, PRDs, CRs, reviews) but has no terminal and cannot write .claude/. That split is intentional — it's what keeps planning and building from colliding.

    Most projects need no "linking" — both tools just open the same folder. The one exception is a framework that runs code from a separate location (e.g. Frappe's bench): there you symlink that location into the folder. The bootstrap discovery prompt (next page) detects this for you.

    4. The one rule to internalise

    Two tools, one folder — never write the same file at the same time. Plan in Cowork → build in Claude Code → review in Cowork. Sequential. Handoffs travel through named files (a PRD, a CR in docs/), never through chat memory. Full reasoning in Methodology.

    5. Verify the wiring

    In Claude Code, ask:

    "List the agents and skills in this project, and tell me when each one fires."

    For a TAP LMS checkout it should name eight agents (prd-author, change-requirement, architecture-reviewer, task-manager, feature-builder, code-reviewer, test-runner, retrospective) and eight frappe-* skills. If it can, the layer is loaded correctly.

    Then a read-only smoke check:

    "Read CLAUDE.md and WORKFLOW.md and summarise the path for a new feature vs. a behavior change."

    If the summary matches WORKFLOW.md, you're set.

    6. (TAP LMS only) wire the bench

    TAP LMS runs from a Frappe bench, so app/ is a symlink into ~/frappe-bench/apps/tap_lms. Bench commands run from ~/frappe-bench. Full steps and the two-folder sync rules: SETUP.md.
