    Frappe (TAP LMS) — local dev install

    Stand up a TAP LMS bench on your own machine for development. Internal doc — not published. Sanitized consolidation of the team's Notion notes.

    🔒 No secrets here. Use throwaway local passwords for the local DB; never reuse a production password locally. Pull any real credential from Secret Manager only when you actually need to talk to a prod-like service.

    TAP-LMS is PostgreSQL + Frappe v15 + Node 18. Two paths: macOS native bench (A) or Docker (B). A is best for day-to-day dev; B is best for a disposable, reproducible env.

    A. macOS native bench (Homebrew)

    # Toolchain
brew install python@3.12 postgresql@16 redis yarn
brew services start postgresql@16
brew services start redis
npm install -g yarn            # if not via brew

# (wkhtmltopdf for PDF/print formats)
brew install --cask wkhtmltopdf

pip3 install frappe-bench
bench init frappe-bench --frappe-branch version-15 --python python3.12
cd frappe-bench

    Create a local Postgres site and get the apps:

    bench new-site tap_lms.dev --db-type postgres --db-host localhost
bench --site tap_lms.dev enable-scheduler
bench use tap_lms.dev

bench get-app --branch pal-v2 https://github.com/DalgoT4D/frappe_tap.git
bench get-app https://github.com/Midocean-Technologies/business_theme_v14.git
bench --site tap_lms.dev install-app tap_lms
bench --site tap_lms.dev install-app business_theme_v14
bench --site tap_lms.dev migrate

    Run it:

    bench start                    # http://tap_lms.dev:8000 (add tap_lms.dev to /etc/hosts -> 127.0.0.1)

    Homebrew nginx/supervisor are optional locally — bench start runs the dev web/worker/scheduler processes directly.

    This is the working folder ↔ bench setup (L-024). In this project, app/tap_lms is a symlink into ~/frappe-bench/apps/tap_lms, so a file edited in either place is the same file. See SETUP.md for the symlink and the two-folder sync rules.

    B. Docker (disposable container)

    A single Ubuntu container running the full stack — handy for a clean, throwaway env. Sketch (sanitized — no baked-in passwords; pass secrets at runtime, not in the image):

    FROM ubuntu:22.04
ARG DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y \
    python3.12 python3.12-dev python3.12-venv python3-pip \
    postgresql postgresql-contrib redis-server \
    supervisor nginx curl git sudo wkhtmltopdf libfontconfig xvfb
# non-root bench user (set the password at run time / via secret, do NOT hardcode)
RUN useradd -m -s /bin/bash frappe && adduser frappe sudo
USER frappe
WORKDIR /home/frappe
# nvm + node 18, then `pip install frappe-bench && bench init ...` as the frappe user
EXPOSE 8000 9000

    Then inside the container, the bench steps are the same as path A (Postgres site, get-app --branch pal-v2, install, migrate). Start services manually (sudo service postgresql start, redis-server, …) then bench start. Snapshot a working container with docker commit <id> tap-lms-dev:base so you can reset quickly.

    Load real data locally

    Most of the time you want prod-like data, not an empty site. Restore a backup into tap_lms.dev following frappe-restore.md — and be sure to apply the non-prod safety toggles in that doc (pause scheduler, mute emails, neuter Glific/webhooks) so your laptop never messages real teachers/students.
