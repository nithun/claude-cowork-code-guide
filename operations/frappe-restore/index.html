    Frappe (TAP LMS) — backup & restore

    Back up a TAP LMS site and restore it into another environment (prod → stage/dev clone, or disaster recovery). Internal doc — not published. Sanitized consolidation of the team's Notion restore notes.

    🔒 Secrets policy. The site encryption_key, DB passwords, and SSH keys are not in this file. Pull them from GCP Secret Manager at run time. The old habit of pasting the encryption_key and .pem keys into Notion is being retired — those are treated as compromised and rotated. Placeholders: <SITE>, <TARGET>, <PROD_HOST>, <SSH_KEY>, <BACKUP_DIR>.

    TAP-LMS is PostgreSQL. (Older notes mention a "MariaDB root password" — that was a copy-paste from other projects; ignore it.)

    0. The one thing people get wrong

    The target's encryption_key must match the source's before you restore. Frappe encrypts secret fields (Glific tokens, OpenAI/RabbitMQ/GCS creds, user passwords) with that key. Restore a DB without setting the matching key first and every encrypted field becomes unreadable junk. Step 4 handles this — don't skip it.

    1. Back up the source site

    On the source/prod bench:

    bench --site <SITE> backup --with-files --include "private-files" --verbose \
  --backup-path <BACKUP_DIR>/$(date +%F)

    This produces four artifacts:

    File Contents
    …-database.sql.gz the Postgres dump
    …-files.tar public files
    …-private-files.tar private files
    …-site_config_backup.json site config incl. the encryption_key — handle as a secret

    2. Transfer to the target

    scp -i ~/.ssh/<SSH_KEY> -r <BACKUP_DIR>/<date> <user>@<TARGET>:<BACKUP_DIR>/

    Use a key issued from your secrets store / OS Login — not a .pem pasted from a doc.

    3. Prepare the target site

    Fresh target (otherwise skip to step 4 against the existing site):

    bench new-site <TARGET> --db-type postgres --db-host localhost
bench --site <TARGET> install-app tap_lms              # match prod branch: pal-v2
bench --site <TARGET> install-app business_theme_v14

    4. Match the encryption_key BEFORE restoring

    Get the source key (from Secret Manager, or grep encryption_key in the backed-up site_config_backup.json), then set it on the target:

    bench --site <TARGET> set-config encryption_key "<encryption-key-from-secret-manager>"

    5. Restore

    bench --site <TARGET> restore \
  <BACKUP_DIR>/<date>/<ts>-<site>-database.sql.gz \
  --with-public-files  <BACKUP_DIR>/<date>/<ts>-<site>-files.tar \
  --with-private-files <BACKUP_DIR>/<date>/<ts>-<site>-private-files.tar

    (The backup's filename prefix is the source site's internal name — that's fine, bench restore only reads the dump contents.)

    6. Post-restore

    bench --site <TARGET> migrate
bench --site <TARGET> clear-cache
bench --site <TARGET> clear-website-cache
bench build
bench restart

    7. Make a non-prod clone SAFE (do this every time)

    A restored clone still holds production integration endpoints and credentials. Before it can touch anything external, neuter it — otherwise your stage/dev box will message real teachers/students via Glific or fire scheduled jobs against live data.

    # Stop scheduled jobs and outgoing mail
bench --site <TARGET> set-config -p pause_scheduler 1
bench --site <TARGET> set-config mute_emails 1
bench --site <TARGET> scheduler disable        # heavier hammer if you want zero risk

    Then point or disable each prod integration (in site_config.json and the relevant Settings DocTypes):

    • Glific API URL + token, and any webhook URLs Glific calls back into — point to a sandbox or blank them.
    • Email Accounts — disable outgoing SMTP records (or rely on mute_emails).
    • AI / RabbitMQ / OpenAI / GCS endpoints + buckets — point to dev equivalents or stub.

    Find candidates quickly:

    bench --site <TARGET> console

    import frappe
rows = frappe.db.sql("""SELECT name, field, value FROM "tabSingles"
    WHERE field ~* 'url|webhook|token|bucket'""", as_dict=True)
for r in rows: print(r)

    8. Verify

    bench --site <TARGET> list-apps
bench --site <TARGET> console
# >>> frappe.db.sql('SELECT count(*) FROM "tabUser"'); exit()
