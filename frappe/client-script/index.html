    Frappe client script skill

    Client scripts run in the desk (the back-office UI) on top of Frappe's form framework. The entry point is a sibling .js file next to the DocType JSON, or a Client Script record stored in the DB. File-based wins for version control; DB-based wins for hot-fixes and per-site overrides.

    Two scopes

    • Form Script — runs on a single document's form view. frappe.ui.form.on("Course Enrollment", { ... }).
    • List View — runs on the list page. frappe.listview_settings["Course Enrollment"] = { ... }.

    There are also frappe.ui.Dialog, report scripts (<report>.js), and Web Form scripts. All speak the same frm/frappe API.

    Form script anatomy

    frappe.ui.form.on("Course Enrollment", {
    refresh(frm) {
        // Runs every time the form is rendered (load, after save, after switching tabs back).
        if (frm.doc.docstatus === 1 && frm.doc.status === "Active") {
            frm.add_custom_button(__("Mark Completed"), () => mark_completed(frm), __("Actions"));
        }
        toggle_certificate_section(frm);
    },

    student(frm) {
        // Runs when the `student` field changes.
        if (!frm.doc.student) return;
        frappe.db.get_value("Student", frm.doc.student, "preferred_language")
            .then(({ message }) => frm.set_value("language", message?.preferred_language));
    },

    validate(frm) {
        // Browser-side validation. Server `validate` still runs — this is for fast UX feedback.
        if (frm.doc.start_date && frm.doc.end_date && frm.doc.start_date > frm.doc.end_date) {
            frappe.throw(__("End date must be after start date"));
        }
    },
});

function toggle_certificate_section(frm) {
    frm.toggle_display("certificate_section", frm.doc.status === "Completed");
}

function mark_completed(frm) {
    frappe.call({
        method: "tap_lms.api.complete_enrollment",
        args: { enrollment: frm.doc.name },
        freeze: true,
        freeze_message: __("Wrapping up..."),
    }).then(() => frm.reload_doc());
}

    The handler keys are: field event names (fires when that field changes), lifecycle events (refresh, setup, onload, validate, before_save, before_submit, before_cancel), and child-table events (<table_field>_add, <table_field>_remove).

    The frm object — what you actually use

    • frm.doc — the current document as a JS object. Mutate via setters, not direct assignment.
    • frm.set_value(field, value) — write to a field; triggers field events and dirty state.
    • frm.set_df_property(field, prop, value) — change a field property on the fly (reqd, read_only, hidden, options).
    • frm.toggle_display(field, condition) / toggle_enable / toggle_reqd — common patterns one-linered.
    • frm.add_custom_button(label, action, group) — adds to the top toolbar; group collapses related buttons under a menu.
    • frm.dashboard.add_indicator(label, color) — pill on the top of the form.
    • frm.refresh_field("table_field") — re-render a child table after programmatic changes.
    • frm.reload_doc() — fetch fresh server state.
    • frm.is_dirty() / frm.dirty() — track unsaved changes.

    Calling the server

    frappe.call({ method, args, freeze }) is the primary RPC. The method must be a whitelisted Python method (@frappe.whitelist()) reachable by dotted path. For DocType methods, use doc: frm.doc, method: "do_thing" to invoke a controller method.

    For lookups, prefer the convenience helpers — they're cheaper than a full frappe.call:

    frappe.db.get_value("Course", course_name, "title");
frappe.db.get_doc("Course", course_name);
frappe.db.get_list("Course Enrollment", { filters: { student }, fields: ["name", "status"] });
frappe.db.exists("Course Enrollment", { student, course });
frappe.db.count("Lesson Progress", { enrollment });

    fetch_from — the lazy man's auto-populate

    Don't write a JS handler to copy a field from a linked doc — declare fetch_from in the DocType JSON instead:

    { "fieldname": "course_title", "fieldtype": "Data", "fetch_from": "course.title", "read_only": 1 }

    Frappe handles the fetch automatically on the course field's change. Use JS only for transformations the JSON can't express.

    Dialogs

    const dialog = new frappe.ui.Dialog({
    title: __("Award Certificate"),
    fields: [
        { fieldname: "issue_date", fieldtype: "Date", label: __("Issue Date"), default: frappe.datetime.get_today(), reqd: 1 },
        { fieldname: "remarks", fieldtype: "Small Text", label: __("Remarks") },
    ],
    primary_action_label: __("Award"),
    primary_action(values) {
        frappe.call({
            method: "tap_lms.api.award_certificate",
            args: { enrollment: frm.doc.name, ...values },
        }).then(() => { dialog.hide(); frm.reload_doc(); });
    },
});
dialog.show();

    List view tweaks

    frappe.listview_settings["Course Enrollment"] = {
    add_fields: ["status", "course", "student"],
    get_indicator(doc) {
        return {
            "Active":    [__("Active"),    "blue",   "status,=,Active"],
            "Completed": [__("Completed"), "green",  "status,=,Completed"],
            "Dropped":   [__("Dropped"),   "red",    "status,=,Dropped"],
        }[doc.status];
    },
    onload(listview) {
        listview.page.add_inner_button(__("Bulk Activate"), () => bulk_activate(listview));
    },
};

    add_fields ensures the fields are in the row payload — without it, doc.status is undefined in get_indicator.

    Translation

    Always wrap UI strings in __("..."). Frappe extracts these for the translation files. __("Hello {0}", [name]) for interpolation.

    When NOT to put it in JS

    • Authorization checks — never trust the browser. The server validate is the source of truth; client checks are for UX, not security.
    • Complex computations — round-trip to a whitelisted method instead.
    • Anything that needs DB writes — write a server method, call it.

    Loading order and caching

    The desk caches .js files aggressively. After editing, run bench --site <site> clear-cache or hit Ctrl-Shift-R in the browser. If you're staring at unchanged behavior, it's the cache — every time.

    File path

    app/<your_app>/<your_module>/doctype/course_enrollment/course_enrollment.js

    For scripts that span multiple DocTypes, use app/<your_app>/public/js/<feature>.js and register it via app_include_js in hooks.py (see the frappe-hooks skill).
