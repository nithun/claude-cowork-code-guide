    Frappe API skill

    STOP — read this first if the endpoint is consumed by Glific: docs/api-standard-glific.md is the binding contract for every @frappe.whitelist() endpoint that Glific calls. It overrides Frappe defaults: NO message wrapper (use frappe.local.response.update()), flat scalars only, no arrays, success + status envelope, HTTP 200 even for business errors, snake_case ASCII keys. Read it end-to-end before writing or modifying the endpoint, and run the curl-test (Rule 10) before declaring done.

    Frappe ships three API surfaces:

    1. Whitelisted methods — RPC-style. You decorate a Python function and it's reachable as /api/method/<dotted.path>. This is the workhorse.
    2. REST resource API — auto-generated CRUD over DocTypes at /api/resource/<DocType>. Good for generic admin tools and simple integrations.
    3. Web view / portal pages — @frappe.whitelist(allow_guest=True) plus a Jinja template, for public-facing endpoints.

    Pick #1 for almost everything custom; #2 only when you genuinely want generic CRUD; #3 for anonymous reads.

    Whitelisted methods

    # app/tap_lms/api.py
import frappe
from frappe import _


@frappe.whitelist()
def enroll(student: str, course: str) -> dict:
    """Enroll a student in a course. Idempotent."""
    if not frappe.db.exists("Student", student):
        frappe.throw(_("Student {0} not found").format(student))
    if not frappe.db.exists("Course", course):
        frappe.throw(_("Course {0} not found").format(course))

    existing = frappe.db.get_value(
        "Course Enrollment",
        {"student": student, "course": course, "status": "Active"},
        "name",
    )
    if existing:
        return {"enrollment": existing, "created": False}

    doc = frappe.get_doc({
        "doctype": "Course Enrollment",
        "student": student,
        "course": course,
        "status": "Active",
    }).insert()
    return {"enrollment": doc.name, "created": True}

    Reachable at:

    POST /api/method/tap_lms.api.enroll
Content-Type: application/x-www-form-urlencoded
student=STU-001&course=CS101

    Returned JSON wraps the value in {"message": ...}. Clients should read response.message.

    allow_guest

    @frappe.whitelist(allow_guest=True)
def public_course_list():
    return frappe.get_all("Course", filters={"is_published": 1}, fields=["name", "title"])

    Without allow_guest=True, the method requires an authenticated session. Be deliberate; guest endpoints are the most common security hole.

    methods=

    @frappe.whitelist(methods=["POST"])
def submit_attempt(...): ...

    Restrict HTTP verbs. Defaults to GET+POST. Use methods=["POST"] for state-changing endpoints so a CSRF-style accidental GET can't trigger a write.

    Type hints and validation

    Frappe doesn't currently coerce types from query strings — everything arrives as strings. Either coerce manually:

    @frappe.whitelist()
def list_attempts(course: str, limit: int = 20) -> list:
    limit = int(limit)
    ...

    Or wrap with pydantic / attrs if your app already uses them.

    REST resource API

    Out of the box:

    • GET /api/resource/Course — list (respects user permissions)
    • GET /api/resource/Course/CS101 — single doc
    • POST /api/resource/Course — create (body = JSON dict)
    • PUT /api/resource/Course/CS101 — update
    • DELETE /api/resource/Course/CS101 — delete

    Query params: ?fields=["name","title"]&filters=[["is_published","=",1]]&limit_page_length=50&order_by=creation desc.

    The resource API runs through the same permission system as the desk. A user/role without read on the DocType gets 403.

    Authentication

    API Key + Secret (preferred for server-to-server)

    User sets up an API Key + API Secret under their User profile. Calling code sends:

    Authorization: token <api_key>:<api_secret>

    Generate programmatically:

    user = frappe.get_doc("User", "integrations@tap.example")
api_secret = frappe.generate_hash(length=15)
user.api_key = frappe.generate_hash(length=15)
user.api_secret = api_secret
user.save(ignore_permissions=True)
# Show api_secret to user once — it's hashed at rest.

    OAuth 2.0

    Frappe is itself an OAuth provider — set up an OAuth Client record, then point a third-party client at /api/method/frappe.integrations.oauth2.authorize. Use this when a user is granting a foreign app access on their behalf. Skip for internal services; API keys are simpler.

    Session cookies

    For SPAs served from the same origin, the session cookie set by /api/method/login works fine. For cross-origin, you'll need to handle CORS (see cors_domains in common_site_config.json) and CSRF (Frappe sets X-Frappe-CSRF-Token for authenticated sessions; pass it back on writes).

    Webhooks (incoming)

    Treat as untrusted input. Verify signatures:

    import hmac, hashlib

@frappe.whitelist(allow_guest=True, methods=["POST"])
def receive_payment_webhook():
    raw = frappe.request.get_data()
    signature = frappe.request.headers.get("X-Webhook-Signature", "")
    expected = hmac.new(
        frappe.conf.payment_webhook_secret.encode(),
        raw,
        hashlib.sha256,
    ).hexdigest()
    if not hmac.compare_digest(signature, expected):
        frappe.throw(_("Bad signature"), exc=frappe.AuthenticationError)

    payload = frappe.parse_json(raw)
    frappe.enqueue(
        "tap_lms.tap_lms.payments.handle_webhook",
        payload=payload,
        queue="short",
    )
    return {"ok": True}

    Always offload work to a queue — webhooks demand fast 200 responses.

    Webhooks (outgoing)

    Frappe has a built-in Webhook DocType: configure URL + headers + body template + trigger DocType + event. No code needed for most outgoing webhooks.

    Rate limiting

    Frappe has a basic per-IP/per-user limiter (enable_rate_limit in site config). For richer needs, put nginx in front and rate-limit there, or wrap the method with a custom decorator that reads/writes a Redis counter via frappe.cache().

    Error responses

    frappe.throw(_("...")) produces a 417 with the message. For RESTful 400/404/403 codes:

    import frappe
from werkzeug.exceptions import NotFound, BadRequest

@frappe.whitelist()
def get_course(name):
    if not frappe.db.exists("Course", name):
        raise NotFound(f"Course {name} not found")
    return frappe.get_doc("Course", name).as_dict()

    Versioning

    Frappe doesn't version /api/method paths. If your API has external consumers, version it yourself by namespace:

    /api/method/tap_lms.api.v1.enroll
/api/method/tap_lms.api.v2.enroll

    Don't break v1 once published.

    Public API contract — parameter names matter

    On TAP LMS, whitelisted method parameter names are public contract. Glific flows reference them directly (and contact-field names too — lesson L-008). Renaming content_id → assignment_id without an alias silently breaks every Glific flow node that calls the API. This has bitten us twice (CR-2026-05-10 #H2).

    Always add a backward-compat alias for at least one release cycle, and log a deprecation warning when the old name is used. Pattern P-006:

    @frappe.whitelist()
def save_submission(student_id, assignment_id=None, content_id=None, **kwargs):
    if assignment_id is None and content_id is not None:
        assignment_id = content_id
        frappe.log_error(
            "Deprecated: save_submission called with content_id; "
            "rename to assignment_id",
            "API deprecation",
        )
    if assignment_id is None:
        frappe.throw(_("assignment_id is required"))
    ...

    Lesson L-009. Code-reviewer flags every rename without an alias as HIGH severity.

    External calls must retry — Glific, RabbitMQ, anything off-box

    Calls to Glific (update_contact_fields, start_contact_flow) and RabbitMQ publishes from inside whitelisted methods need retry + dead-letter behaviour. The state has already committed in PG by the time the external call runs; a silent failure leaves Glific cache stale or submissions lost (CR-2026-05-10 #H3, #H4).

    Use frappe.enqueue with retry=N rather than calling the external service inline:

    def _sync_contact_fields(pe):
    try:
        update_contact_fields(pe.glific_id, build_field_dict(pe))
    except Exception as e:
        frappe.log_error(
            f"Glific sync failed for {pe.glific_id}: {e}",
            "Glific sync",
        )
        frappe.enqueue(
            "tap_lms.summer_program.glific_extensions.retry_contact_fields",
            queue="short", retry=3,
            pe_name=pe.name,
        )

    Lesson L-015, pattern P-007.

    Glific contact fields require TWO mutations, not one

    updateContact (the mutation we used for years) writes a value into the contact's fields JSON column but does not register the field's DEFINITION. Without a definition row in Glific's contacts_fields table, the field is invisible to the Flow Editor: no dropdown entry, @contact.fields.<shortcode> renders as literal text, and webhook query params can't surface it. Confirmed by Glific support 2026-05-26.

    3-step protocol when adding any new contact field:

    1. Add the CF_X = "shortcode" constant in summer_program/constants.py.
    2. Add it to every push payload that should carry the field:
    3. state_machine._enqueue_contact_field_sync (recurring per-transition sync)
    4. program_enrollment_api._process_pe_chunk and process_glific_contact (enrollment-time push)
    5. dev_tools.reconcile_pe_to_glific (operator-driven reconcile)
    6. Add (shortcode, "Display Name") to SP_CONTACT_FIELD_DEFINITIONS in dev_tools.py AND re-run dev_tools.bootstrap_sp_contact_fields() on every Glific org (dev, prod). The helper is idempotent — already-registered fields return "shortcode already taken" which we treat as success.

    Skipping step 3 means the value lands in the JSON cache (visible in the contact profile) but flow templates render @contact.fields.X as literal text.

    Multi-tenant Glific boundary. Several programs share the same Glific organization (TLM, scert, pocflow, plus SP). Legacy keys like streak, gems, bonus_points, current_activity_points are owned by other programs — the SP backend must not write to them. The SP namespace is exactly the 29-30 fields registered by bootstrap_sp_contact_fields(). Writing outside that namespace silently clobbers data other programs depend on. Lesson L-053.

    Audit-field-as-idempotency-anchor pattern

    When the same logical write can be produced by multiple writers (sync API + async worker; in-request handler + scheduled cron), an audit column on the row coordinates them without locking. Pre-fill the field at the upstream-write site; downstream hooks gate on the field to skip:

    # In-request handler awards points and pre-fills the audit field
@frappe.whitelist()
def complete_content(student_id, content_id, ...):
    pts = award_points_now(student_id, content_id)
    frappe.enqueue(
        "tap_lms.summer_program.background_jobs.job_log_content_completion",
        queue="short",
        student_id=student_id,
        content_id=content_id,
        points_awarded=pts,   # ← carry the already-awarded amount
        ...
    )

# Worker creates the audit row with points_awarded ALREADY SET
def job_log_content_completion(student_id, content_id, points_awarded=None, ...):
    log = frappe.get_doc({
        "doctype": "StudentContentLog",
        ...,
        "points_awarded": cint(points_awarded) if points_awarded is not None else 0,
    })
    log.insert(ignore_permissions=True)

# after_insert hook reads the gate field and skips if upstream awarded
def handle_content_log(scl, method=None):
    if (scl.points_awarded or 0) > 0:
        return   # already awarded by upstream caller; nothing to do
    award_points(scl)

    The pattern is pattern P-010 (proposed; full form expanded from P-005 "idempotency anchor written first"). Used correctly, it eliminates the need for cross-process locks for write-once audit data.

    Good API hygiene

    • Return predictable shapes. Don't return a Document one call and a dict the next.
    • Document each endpoint with a docstring; bench generates docs from them.
    • Use frappe.has_permission(doctype, ptype, doc=name) to check permissions explicitly when bypassing default checks.
    • Log unusual conditions via frappe.log_error(message, title). They land in the Error Log DocType and are filterable.

    Testing API endpoints

    bench --site <site> execute tap_lms.api.enroll --kwargs '{"student": "STU-001", "course": "CS101"}' runs a method with the desired session. Combine with bench console for ad-hoc poking.

    For automated tests, see the frappe-test skill — Frappe's test runner sets up an authenticated context so you can call whitelisted methods directly.
