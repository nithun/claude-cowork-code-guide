    How to use claude-cowork-code

    🌐 Published at nithun.github.io/claude-cowork-code-guide

    This is the team handbook for the Cowork + Claude Code way of building software at TAP. It assumes nothing about Frappe — the method works on any stack. Where TAP LMS is used as an example, it's labelled.

    What this gives you

    • Cowork does the thinking on paper — ideas, specs, change requests, reviews.
    • Claude Code does the building — code, tests, running things, maintaining the agent layer.
    • A set of subagents that each own one step (write the PRD, scope the change, build it, review it, test it), and a memory + retrospective loop that turns recurring mistakes into rules so the project gets more correct over time.

    The whole thing is held together by one rule: two tools, one folder, never the same file at once. Handoffs go through named files, not chat.

    Reading order (first time)

    1. Getting started — install the two tools, open a project, confirm it's wired.
    2. Methodology — the mental model: the two-tool rule, the agents, the memory loop. ~10 min. (The loop in depth: How the system improves itself.)
    3. Then whichever playbook matches your role (product or engineering).
    4. When you start a new repo: a Frappe app (the common case) or a different stack. Writing Frappe code? Keep the Frappe reference skills handy.

    The shape of a day

    Cowork:  "Write a PRD for X"           → docs/prds/PRD-NNN.md
Cowork:  "Write a CR for behavior Y"   → docs/change-requests/CR-NNN.md
  (you review and approve the doc)
Code:    "Implement CR-NNN"            → code + tests, then review + test run
  (you copy to the running env, commit, deploy)
Code:    "Run retrospective"           → the system learns from the work

    Same loop on every project. The agents and skills change per stack; the loop doesn't.
